DONE / EVIDENCE
- Fixed inconsistent red vertical line indicator on flagged scan rows in Admin -> Scan Logs:
  * Identified Root Cause:
    - In frontend/src/pages/Logs.tsx (line 571), rowClassName applies the red indicator class when scan.flagged is true:
        rowClassName={(scan) => scan.flagged ? 'border-l-3 border-l-red-500 bg-red-500/[0.03]' : ''}
    - In frontend/src/components/ui/table.tsx (line 34), TableBody previously had:
        className={cn("[&_tr:last-child]:border-0", className)}
    - In CSS, border-0 sets all border widths to 0px (border-top, border-right, border-bottom, border-left).
    - Because the selector tbody tr:last-child has higher specificity than the utility class .border-l-3,
      it unconditionally erased the left border on the last row of the table.
    - In the user's view (/logs?attention=review&status=Flagged), exactly 2 scans were listed. The second scan was
      tr:last-child in tbody, causing its red left-side indicator to be wiped out despite having scan.flagged = true
      and displaying the red flag icon.
    - TableRow only has border-b (border-bottom), and TableFooter in table.tsx already correctly used [&>tr]:last:border-b-0.
  * Applied Minimal & Targeted Fix:
    - In frontend/src/components/ui/table.tsx: updated TableBody className from [&_tr:last-child]:border-0 to [&_tr:last-child]:border-b-0.
    - This removes only the bottom border from the last row (preventing double border with table bottom edge) while preserving
      row-level left indicator borders (.border-l-3 border-l-red-500) on all rows, including the last child.
  * Preserved Logic and Design:
    - Maintained exact review vs flagged distinction: scans with low confidence that are not explicitly flagged retain flagged = false
      and do not display the red indicator. Only explicitly flagged scans (flagged = true) display the red indicator.
    - Inventory statuses (In Stock, Sold, Spoiled, For Processing) do not interfere with the indicator.
    - Dashboard Pending Quality Reviews KPI, Scan Logs filters (attention=review and status=Flagged), and Scan Detail actions remain synchronized.
    - Preserved existing UI layout, typography, components, and spacing strictly.
