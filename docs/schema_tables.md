# BananaVision Database Tables

Current application schema at Alembic revision `0009_camera_slots`, generated from an
isolated PostgreSQL 17.10 database. The source DDL is
[`bananavision_schema_current.sql`](bananavision_schema_current.sql); the technical
`alembic_version` table is excluded from this dictionary.

The schema contains **24 application tables**, 7 PostgreSQL enum types and 18 foreign-key
relationships. Table and column identifiers are shown in uppercase for readability; the
actual PostgreSQL identifiers are lowercase snake_case.

Columns are listed primary key first, regular columns next and foreign-key columns last to
match the ERD layout. `PK` and `FK` identify key roles. `FK Referenced Table` shows the
target primary key. Blank **Default** means there is no database-level default: UUID keys,
timestamps and most status defaults are generated by the application (for example
`uuid4`, `now_manila` and `Offline`). `SERIAL` is shorthand for an `INTEGER`
column backed by an owned PostgreSQL sequence.

## Enum types

SQLAlchemy stores Python enum member names by default, so several PostgreSQL labels are
uppercase even though the API returns title-case values. The table shows both forms.

| `cultivarenum` | `LAKATAN`, `LATUNDAN`, `CARDABA` | Lakatan, Latundan, Cardaba |
| `devicestatusenum` | `ONLINE`, `OFFLINE` | Online, Offline |

## Schema notes

- `device.slot_index` and `device.device_index` are the saved camera-slot mapping.
  `SLOT_INDEX` is unique and range-checked to `0..3`; both columns are nullable only for
  operational rows that were never assigned to a saved slot. PostgreSQL unique constraints
  allow multiple `NULL` values.
- `system_config` no longer contains `camera_ids`/`camera_device_ids`; the configuration
  API derives the ordered camera list from the normalized device slots.
- `operator_profile` no longer contains `total_scans`/`flagged_scans`; analytics derives
  those totals from `scan` rows.
- `maintenance_state` is a database-enforced singleton (`ID = 1`). `system_config` is an
  application-enforced revisioned singleton with an optional `CANONICAL_KEY = 1` marker
  and legacy-conflict flag.
- `scan_event` is append-only revision history; `scan_mutation` stores idempotency receipts;
  `scan_tombstone` records deleted scans without a foreign key to the deleted row.
- All timestamps are `TIMESTAMP WITH TIME ZONE`. Business date boundaries and display
  conversions use the backend Asia/Manila helpers.

For the exact PostgreSQL DDL, enum definitions, sequences, defaults and constraint names,
use [`bananavision_schema_current.sql`](bananavision_schema_current.sql).
