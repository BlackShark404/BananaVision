PREVIOUS RESUME (2026-11-18) - THUMBNAILS, IMAGE CACHE AND DEFERRED FETCH

User asked whether list image previews/thumbnails are optimized. Option 1 (server
thumbnails) and then options 1+2 (in-memory blob cache and true lazy fetch) were approved
and implemented. The server thumbnail work is committed as 10a3b8a; the cache and deferred
fetch remain uncommitted.

WHAT CHANGED
- GET /captures/{scan_id}/{filename}?variant=thumb returns a 256 px max-side JPEG
  (quality 75) generated with cv2 and cached at <capture root>/<scan>/.thumbs/<name>.jpg.
  Existing authorization, allowlist, symlink checks and "private, no-store" headers are
  unchanged. Unsupported variants, unreadable originals and unsafe paths return 404.
- Generation runs through run_blocking, uses an atomic temp-file replace, and regenerates
  only when the cache is older than the original. No database migration; old scans get a
  thumbnail on first request. Capture cleanup removes the cache with the scan directory.
- Scan Logs and Quality Control rows now request the thumb variant. Scan Detail and Kiosk
  keep their original evidence URLs. Table ScanImage elements use loading="lazy" and
  decoding="async".
- ScanImage caches protected thumb blobs in memory, keyed by user and URL, with entry and
  byte limits. Remounts reuse the object URL. clearToken() clears and revokes the cache on
  logout or session expiry; originals keep per-mount object URLs.
- Table thumbnails pass defer: an IntersectionObserver with a 200 px margin holds the
  authenticated fetch until the placeholder nears the viewport. Native loading="lazy"
  cannot defer that fetch. Files: frontend/src/lib/imageCache.ts and
  frontend/src/components/ScanImage.tsx.

AUTO-FLAG FIX (user request 2026-11-18; commits 320e480 and 0f61681)
- Request: "Fix the autoflag of the system. It auto flags a kiosk scan in the scan logs and
  quality control even though the average confidence of the kiosk scan is more than the
  default of 80% confidence threshold."
- Decision: "The auto flag must work in confidence is below the threshold only. No other
  factors needed." Old flags: "Clean up with a preview".
- backend/app/services/fusion_engine.py: auto_flagged = final confidence < review
  threshold, nothing else. FusedResult.flag_reason holds the sentence. The other signals
  (cultivar/ripeness/view conflicts, weak pair support, insufficient views, missing
  captures, different finger counts) are FusedResult.observations.
- backend/app/services/scan_service.py: flags only on fusion's rule. Dropped boxes and
  observations go to the scan_created activity entry after "; noted: ...". A flagged scan's
  created history entry, activity entry and notification say "Confidence X% is below the
  Y% threshold".
- backend/scripts/evaluate_finger_count.py mirrors the rule and reports "noted".
- backend/scripts/review_auto_flags.py: station command for old flags. Preview by default.
  `--apply --admin <username>` removes flags the rule would not set. It never touches
  scans below the threshold, scans a person flagged/corrected/noted, or scans without a
  stored confidence. NOT run by the assistant; the station admin runs it.
- Frontend: the Scan Detail cultivar-disagreement notice mentions clearing the flag only
  when the scan is flagged.
- Docs: Development Decisions (2026-11-18 entry), Resolved Bugs, AI Models, Testing and
  Validation, backend README.
