# Hardware Specification

Hardware specification provides a detailed description of the technical characteristics, capabilities, and requirements of the hardware components used in a system. It defines key attributes such as operating parameters, sensor types, communication interfaces, resolution, power requirements, and mechanical features that determine system performance and compatibility. For BananaVision, the hardware specification serves as a guide for selecting, integrating, deploying, and maintaining the physical components required to support multi-angle banana image capture, environmental sensing, classification label printing, and station operation at agricultural inspection points.

At the core of the BananaVision inspection station is a four-camera USB webcam array arranged in fixed positions to capture comprehensive multi-angle views of banana bunches during each scan cycle. The four cameras are designated as Top (overhead, directly downward-facing), Left (lateral side view), Right (lateral side view), and Rear (inner concave and underside view), providing spatial coverage that ensures all visible surfaces of the banana bunch are photographed for classification. Each camera operates at a default resolution of 1920×1080 pixels using the MJPG video codec at 15 frames per second, with capture quality set to 95% JPEG compression. The cameras connect directly to the station computer via individual USB ports rather than through a USB hub, as direct connections have been validated for reliable simultaneous capture without bandwidth contention.

The camera system is managed through the OpenCV library using the DirectShow backend on Windows, which provides low-level access to camera device enumeration, resolution configuration, and frame acquisition. Upon system startup, 30 warmup frames are discarded from each camera to allow automatic exposure and white balance to stabilize before the first scan capture. Each camera is assigned a configurable capture timeout of 3000 milliseconds to prevent pipeline stalls from unresponsive devices. Autofocus is disabled by default with manual focus set to a calibrated value of 25 to ensure consistent focal distance across scan cycles. The cv2-enumerate-cameras library enables device discovery by name and index through the Windows DirectShow API, allowing administrators to map physical camera positions to their detected device indices through the System Configuration interface. This mapping is persisted in the system configuration database and survives application restarts. Camera online and offline status is monitored in real time through WebSocket events broadcast to the Device Status and Kiosk interfaces, enabling operators and administrators to identify disconnected or malfunctioning cameras immediately.

Environmental conditions at the inspection station are monitored using a DHT22 digital temperature and humidity sensor connected to an Arduino microcontroller. The DHT22 is a capacitive humidity sensor paired with a thermistor, capable of measuring temperature within a range of −40°C to 80°C with ±0.5°C accuracy and relative humidity from 0% to 100% with ±2–5% accuracy. The sensor provides digital output through a single-wire protocol, making it straightforward to interface with the Arduino's GPIO pins. The Arduino microcontroller reads the DHT22 sensor data and transmits it to the BananaVision backend server over a USB serial connection at 9600 baud. The data is transmitted in a structured text format and polled by the backend's sensor reader service every 5 seconds. In BananaVision, the temperature and humidity readings serve two primary purposes: they are displayed in the kiosk and dashboard interfaces for real-time environmental awareness, and they are fed as input features into the spoilage prediction model. The spoilage model uses temperature and humidity along with derived features such as Vapor Pressure Deficit, calculated using the Magnus-Tetens formula, dew point temperature, and heat index to estimate the number of days remaining before the classified banana bunch reaches spoilage. This environmental integration ensures that spoilage predictions account for actual post-harvest storage conditions rather than relying solely on visual ripeness assessment.

Scan result labeling is performed by a Grozziie TP870 S thermal label printer connected to the station computer via USB. The TP870 S is a direct thermal printer that operates without ink cartridges or toner, using heat-sensitive label stock to produce durable printed output. It is configured to print on 40mm wide by 30mm high adhesive labels, which are applied to banana bunches or their packaging after successful classification. Each printed label contains a machine-readable QR code encoding the scan identifier, classified cultivar, ripeness stage, spoilage prediction in days, detection confidence percentage, and the temperature and humidity readings at the time of scan. Adjacent to the QR code, a human-readable panel displays the same information in text format for manual verification. The QR code links to a public tracking page accessible via any smartphone or QR scanner without authentication, enabling downstream buyers, handlers, and quality inspectors to verify the provenance and classification of labeled produce. Label printing is managed through the Windows GDI printing API via the pywin32 library, which provides direct control over the print device context, text rendering, and QR code bitmap placement. The system supports manual batch printing of one to ten labels from the Scan Logs interface, automatic printing triggered immediately after a successful scan cycle, and demo printing that generates a single label marked "DEMO" for calibration and testing purposes.

The BananaVision inspection station is powered by a Mini PC or edge computing device that serves as the central processing unit for image capture, AI inference, database management, and web application hosting. The station computer requires an x86_64 processor capable of running Python 3.12, PostgreSQL, and the PyTorch deep learning framework simultaneously. A minimum of 8 GB of RAM is required to support concurrent YOLO model loading, multi-camera frame buffering, database query execution, and web server request handling, with 16 GB recommended for production deployments where multiple operators may be scanning and reviewing results concurrently. An NVIDIA GPU with CUDA support is strongly recommended for accelerated YOLO inference, enabling real-time detection and classification across all four camera views within acceptable latency bounds. The system automatically detects and utilizes available CUDA devices, falling back to CPU-only inference when no compatible GPU is present. A solid-state drive is recommended for fast read and write access to captured image files and the PostgreSQL database, as each scan cycle generates four high-resolution JPEG images stored locally with a configurable retention period defaulting to 30 days. The station computer must provide a minimum of six USB ports: four for the camera array, one for the Arduino sensor module, and one for the thermal label printer.

The kiosk display serves as the primary visual interface for station operators interacting with the BananaVision system during banana inspection. The display is connected to the station computer and runs Google Chrome or Chromium in fullscreen kiosk mode, presenting the web application without browser navigation bars, toolbars, or address fields. This configuration provides an appliance-like user experience where operators interact exclusively with the scanning interface through touch input or a connected mouse and keyboard. The display renders live camera preview feeds, real-time scan progress updates through WebSocket events, classification results with bounding box overlays, and environmental sensor readings. The system provides automatic kiosk startup through platform-specific launcher scripts that initialize the backend server, open the browser in kiosk mode, and navigate to the scanning interface, with auto-login configured at the operating system level to ensure the station boots directly into the operational state without manual intervention.

The physical inspection environment consists of a flat inspection platter or tray where banana bunches are placed for scanning, positioned within the field of view of all four cameras. The Top camera is mounted directly above the inspection area looking straight down to capture the overhead view without perspective foreshortening, while the Left, Right, and Rear cameras are positioned at lateral angles to capture side profiles, surface texture, and the inner concave regions of the bunch. Consistent, diffused lighting within the inspection area is recommended to minimize shadows, specular highlights, and color temperature variation across camera views, as the YOLO classification model's accuracy is sensitive to illumination consistency. The enclosed or semi-enclosed design reduces interference from ambient light changes throughout the day, ensuring that captured images maintain uniform brightness and contrast for reliable cultivar and ripeness detection across successive scan cycles. The arrangement ensures that detection artifacts from background elements such as door frames, window jambs, ceiling structures, and table edges are identified and suppressed through the classification pipeline's post-processing filters.

The inspection station operates on standard AC mains power through a regulated power supply unit integrated into the station computer. The power supply provides stable DC voltage to the Mini PC, which in turn supplies power to connected USB peripherals including the camera array, Arduino sensor module, and thermal label printer. A surge protection device or uninterruptible power supply is recommended to protect the station hardware from voltage fluctuations, power surges, and brief outages that are common in agricultural and warehouse environments. The system includes software-managed power control capabilities through the administrative interface, supporting controlled operating system shutdown and restart commands. The maintenance state machine coordinates power operations by first transitioning the system into a draining state where new scan admissions are closed, allowing any active scan pipeline to complete before executing the power command. This ensures that no scan data is lost or corrupted during planned shutdowns or restarts, and that the database and capture storage remain in a consistent state.

For system access and management, the web platform requires a computer running Windows 10 or macOS Catalina or higher, with a dual-core processor, at least 4 GB of RAM, sufficient storage capacity, and a stable local network connection. On the station side, the BananaVision application supports deployment on Mini PCs or edge computing devices running Windows 10 or higher or Linux with a desktop environment, with adequate processing power, memory, GPU capability, and USB connectivity to ensure smooth operation and real-time classification.

Overall, the defined hardware specifications ensure that BananaVision operates reliably under post-harvest inspection conditions, supports accurate multi-angle image capture for AI-driven classification, and maintains efficient communication across all station components. This hardware configuration enables precise banana ripeness assessment, real-time environmental monitoring, durable label printing, and long-term deployment in agricultural processing environments.
