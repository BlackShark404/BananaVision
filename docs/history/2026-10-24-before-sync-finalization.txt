- Backend post-commit mutation events. New backend/app/ws/mutations.py publishes only after the
  owning transaction commits. scan:changed carries event_id, scan_id, revision, kind, changed
  fields, actor_id, partial/deleted flags and the authorized row fields needed for a patch.
  intake:changed and supplier:changed carry event_id plus the persisted row (including updated_at).
- Routing is account-scoped: scan edits go to the dashboard room (Admin) and the owning Operator's
  account-scoped kiosk room. Intake/supplier reference changes go to dashboard and kiosk because
  every authenticated role can read that registry. Other Operators receive nothing.
- Covered commits: scan flag, correction, inventory status, provenance and notes; intake create,
  status and bulk inventory; supplier create/update. Guests and restricted socket rooms are
  unchanged. There is no scan or intake delete/archive endpoint in this application (410 is only
  reachable for rows already removed), so no delete event path exists to add; the `deleted` flag is
  carried only for completeness.
- Mutation endpoints that previously relied on the request-scoped session commit now commit
  explicitly before broadcasting (intakes, suppliers, mutate_scan), so no event can describe an
  uncommitted row. Bulk inventory emits one partial scan event per changed scan plus an intake event
  and never broadcasts note text or images.
- Sensor freshness evidence. GET /api/v1/sensors/latest, the sensor WebSocket payloads and /health
  now include server_time and stale_after_seconds (max(3 x polling interval, 15)). A reading is
  live only while its recorded_at age is within that window; sensor_connected alone is not
  freshness.
- Frontend reconciliation. lib/liveEvents.ts defines SCAN_UPDATED_EVENT, INTAKE_CHANGED_EVENT,
  SUPPLIER_CHANGED_EVENT and a bounded event-id dedupe helper. ScanContext merges by stable ID and
  revision, preserves newer local revisions and fields omitted by partial payloads, removes deleted
  rows and drops stale events. InventoryContext merges intakes/suppliers with updated_at ordering
  and reconciles on resume. useDashboardResource exposes patch() and re-fetches on focus, online,
  visibility and LIVE_RESUMED_EVENT with abort/sequence guards.
- Scan Logs keeps its frozen snapshot behavior. Visible rows are patched in place by revision;
  when a control is focused or an edit is pending, a remote change only shows a non-intrusive
  notice. Deleted or filtered-out rows are removed instead of being shown as current. Page 1 still
  auto-refreshes for new Kiosk scans; Page 2+ keeps rows/page/filters/sort/scroll and the existing
  View Latest Scans / Later notice. Pending counts remain new-commit only, so ordinary edits never
  increment them. 409/410 snapshot recovery and stable exports are unchanged.
- AdminContext, AppNotifications and DeviceStatus also reconcile on reconnect/restore.
  DeviceStatus accepts only newer timestamped readings, rejects out-of-order readings, lets a
  timestamped reading keep authority over a delayed untimestamped initial fetch, and shows legacy
  payloads without recorded_at as unknown freshness - never Live or Optimal.
- Tests added: backend/tests/test_mutation_events.py (7 cases) and
  frontend/tests/crosssession.test.mjs + crosssession.fixture.tsx (9 cases using separate browser
