# Implementation / Deployment Phase

## Software Specifications

A software specification defines the functional and non-functional software requirements needed to support system operation, data processing, communication, and deployment. For BananaVision, the software specification outlines the tools, platforms, frameworks, and system requirements that enable reliable multi-camera banana ripeness detection, real-time AI classification, and web-based inspection management within the networked kiosk station.

During system development, various software tools were used to design, implement, and test BananaVision. Microsoft Word and Google Docs were utilized for documentation and report preparation, while Canva and Figma were used to design system visuals, user interface mockups, and presentation materials. Google Chrome served as the primary browser for accessing the web application interface, testing responsive layouts, and verifying kiosk mode behavior. Visual Studio Code was used as the main code editor for writing and debugging both the frontend application and backend API server. Google Gemini AI (Antigravity) was utilized as a support tool to assist with code architecture, debugging, and feature implementation throughout the development lifecycle.

The frontend web application was built using React 19 as the primary user interface framework, written in TypeScript 5.9 for type-safe component development. Vite 7.3 was employed as the build tool and development server, providing fast hot module replacement during development and optimized production builds. Tailwind CSS 4.2 was used for utility-first responsive styling, and shadcn/ui with Radix UI primitives provided accessible, pre-built interface components including dialogs, dropdown menus, tooltips, tables, and carousels. React Router DOM 7.13 handled client-side navigation across the application's pages. Additional frontend libraries included Recharts 3.8 for interactive analytics charts, Sonner for toast notifications, Embla Carousel for image slideshows, Lucide React for iconography, and the qrcode library for generating scannable QR codes on printed labels and public tracking pages. ESLint 9.39 with TypeScript ESLint and Prettier 3.8 with Tailwind CSS plugin were configured for code linting and consistent formatting throughout the frontend codebase.

The backend API server was implemented using Python 3.12 with FastAPI 0.136 as the asynchronous web framework, chosen for its high performance, automatic API documentation generation, and native support for asynchronous request handling. Uvicorn 0.44 served as the ASGI application server. SQLAlchemy 2.0 with asynchronous session management provided the object-relational mapping layer for PostgreSQL database interactions, while asyncpg 0.31 served as the high-performance asynchronous driver. Alembic 1.18 was used for version-controlled database schema migrations as features were added incrementally. Pydantic 2.13 handled data validation and serialization for all API request and response models. PyJWT 2.10 and bcrypt 5.0 were used for JSON Web Token authentication and secure password hashing, respectively. Real-time communication between the server and connected browser clients was implemented through native FastAPI WebSocket support with room-based publish-subscribe messaging, enabling live scan progress updates, sensor readings, device status changes, and notification delivery.

The artificial intelligence and machine learning pipeline was built using Ultralytics YOLO 8.4 for object detection and banana classification, trained on a custom dataset of Philippine banana cultivars and ripeness stages. PyTorch 2.11 with TorchVision 0.26 served as the underlying deep learning framework, supporting both CUDA-accelerated GPU inference and CPU-only fallback. OpenCV 4.13 was used extensively for image capture from USB cameras, image preprocessing, bounding box rendering, and camera device enumeration through the DirectShow backend on Windows. scikit-learn 1.8 provided the Random Forest Regression model used for spoilage prediction based on classification results and environmental sensor data. NumPy 2.4 and SciPy 1.17 supported numerical computation for feature engineering, including Vapor Pressure Deficit calculation using the Magnus-Tetens formula. The cv2-enumerate-cameras library enabled Windows-specific camera device discovery by name and index. pyserial 3.5 provided serial communication with the Arduino microcontroller for reading DHT22 temperature and humidity sensor data. psutil 7.2 was used for real-time system resource monitoring, reporting CPU, memory, and disk utilization through the administrative interface.

For testing, pytest 9.0 with pytest-asyncio 1.4 was used for backend unit and integration testing against disposable PostgreSQL schemas. The frontend test suite used the Node.js built-in test runner integrated with Playwright for browser-level regression testing, simulating user interactions on both desktop and mobile viewports using Chromium and Microsoft Edge.

For system implementation and deployment, BananaVision operates on commonly available computing hardware to ensure accessibility and reliability at agricultural inspection stations. The inspection station server requires a computer running Windows 10 or Windows 11 for full compatibility with DirectShow camera access, native thermal printer support via pywin32, and the cv2-enumerate-cameras device discovery library, or alternatively a Linux distribution such as Ubuntu or Debian with a desktop environment for kiosk display support. The station computer requires a minimum of 8 GB of RAM to support simultaneous PyTorch model loading, YOLO inference across multiple camera streams, and PostgreSQL database operations, with 16 GB recommended for optimal performance. An x86_64 processor is required, with an NVIDIA GPU supporting CUDA acceleration strongly recommended for real-time inference throughput; the system operates in CPU-only mode when no compatible GPU is available, though inference latency increases. A solid-state drive is recommended for fast image capture storage and database access. The station requires a minimum of four available USB ports for the camera array, one USB port for the Arduino sensor module, and one USB port for the thermal label printer, along with a stable local network connection. Python 3.12 or higher, Node.js, and a running PostgreSQL database instance are required for operating the backend server and building the frontend application. Google Chrome or Chromium is used to access and present the kiosk scanning interface in fullscreen mode.

On the administrative and remote access side, the BananaVision web portal is designed for access through any modern browser on a computer running Windows 10, macOS Catalina, or a current Linux distribution, with at least 4 GB of RAM, sufficient storage capacity, and a stable local network connection to the station server. An internet connection is not required for core inspection operations; the system operates entirely on the local network, with all AI models, database records, and captured images hosted on the station computer. These software requirements ensure reliable classification, secure multi-user access, comprehensive audit logging, and efficient data management across all BananaVision system components.

Overall, the defined software specification supports the operational design of BananaVision by enabling accurate, real-time banana ripeness classification, secure role-based access control, comprehensive audit trails, and reliable data persistence across all system components. This configuration ensures that the inspection, classification, and inventory management functions operate efficiently within agricultural post-harvest processing environments.
