DONE / EVIDENCE
- QR Code Mobile Redirect — public scan tracking without authentication:

  Problem: QR codes on printed banana tags encoded /scans/{id}, which required
  login. Mobile users scanning the QR code were bounced to the landing page.

  Root cause: Both the frontend route (/scans/:scanId inside ProtectedRoute)
  and the backend API (GET /api/v1/scans/{id} requiring CurrentUser) block
  unauthenticated access.

  Solution: Added a parallel public path:
  1. Backend: new GET /api/v1/scans/{id}/track endpoint (no auth) returning
     PublicScanResponse — only classification data, no PII/flags/notes/history.
     (backend/app/api/v1/scans.py, backend/app/schemas/scan.py)
  2. Frontend: new /track/:scanId route outside ProtectedRoute, served by
     PublicScanView.tsx — mobile-friendly summary card with cultivar, ripeness,
     confidence, spoilage, finger count, environmental data, camera images.
     Authenticated users auto-redirect to full /scans/:scanId detail page.
     (frontend/src/pages/PublicScanView.tsx, frontend/src/App.tsx)
  3. QR URL changed from /scans/ → /track/ in qrcode.ts.
  4. Public API method api.scans.publicTrack() added — fetches without
     Authorization header, no 401 redirect. (frontend/src/lib/api.ts)

  Security: Public endpoint excludes operator names, admin notes, flag status,
  override history, provenance details. Only scan UUID (non-sequential) exposed.
